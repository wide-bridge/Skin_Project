# 072 실제 폴더 이행 계획 및 체크리스트 초안

## 1. 목적
- 오늘 당장 옮길 것과 아직 옮기지 말 것을 명확히 구분한다.
- 내일 진행할 주름 + 피부진단 웹 PoC에 영향 없는 안전한 범위만 먼저 정리한다.
- 프로세스 5, 6에서 실제 이동을 수행할 때 실험 재현성과 경로 안정성을 깨뜨리지 않도록 사전 체크리스트와 순서표를 확정한다.

## 2. 앞선 프로세스와의 정합성
### 2-1. 프로세스 1과의 정합성
- `Skin_wrinkle_proj`, `Skin_diagnosis_proj`, `skin_crop_data`는 활성 자산으로 유지한다.
- `Skin_Proj`는 archive 후보지만, 즉시 대규모 이동이나 삭제는 하지 않는다.
- 현재 `wrinkle`, `diagnosis` 모두 절대경로 또는 위치 의존이 있으므로 무리한 물리 이동은 금지한다.

### 2-2. 프로세스 2와의 정합성
- [070_상위_하이어라키_설계_초안.md](./070_상위_하이어라키_설계_초안.md)는 목표 상위 구조를 정의한 문서다.
- 본 문서는 그 목표 구조를 실제로 이행할 때의 순서와 금지 범위를 규정한다.
- 즉 `070`이 목표 구조 문서라면, 본 문서는 목표 구조로 가기 위한 실제 이동 통제 문서다.

### 2-3. 프로세스 3과의 정합성
- [071_wrinkle_프로젝트_상위_편입_규칙_초안.md](./071_wrinkle_프로젝트_상위_편입_규칙_초안.md)에서 `Skin_wrinkle_proj`는 현재 위치 유지가 원칙으로 정리되었다.
- 본 문서는 그 원칙을 유지한 채, 어떤 보조 구조부터 먼저 만들고 어떤 자산은 끝까지 보류할지 정리한다.
- 따라서 프로세스 4는 프로세스 3을 뒤집는 문서가 아니라, 프로세스 5와 6의 실행 순서를 안전하게 만드는 문서다.

## 3. 현재 제약 요약
### 3-1. wrinkle 경로 제약
- `Skin_wrinkle_proj/scripts`에는 `Set-Location`, `SKIN_CROP_ROOT`, `D:/vibe_coding/codex/Skin_Project/...` 계열 경로 의존이 남아 있다.
- 따라서 `Skin_wrinkle_proj`와 `skin_crop_data`를 지금 바로 옮기면 실행이 깨질 가능성이 높다.

### 3-2. diagnosis 경로 제약
- `Skin_diagnosis_proj/scripts/run_api.ps1`
- `Skin_diagnosis_proj/scripts/run_phase04_long_training.ps1`
- `Skin_diagnosis_proj/scripts/run_qwen_phase04_train.ps1`
- 위 스크립트들은 `PYTHONPATH` 또는 프로젝트 루트 절대경로를 직접 사용한다.
- 따라서 `Skin_diagnosis_proj`의 대규모 이동이나 리팩터링은 오늘 범위에서 제외한다.

### 3-3. 산출물 제약
- `outputs`, `checkpoints`, `logs`는 현재 재현성과 이력 확인의 핵심 자산이다.
- 오늘 이들을 옮기면 실험 이력과 웹 PoC 기준선 추적이 오히려 더 불안정해질 수 있다.

## 5. 오늘 이동 가능한 것
오늘 실제로 이동해도 되는 범위는 매우 제한적이다.

### 5-1. 이동 가능
- 상위 `docs/hierarchy` 문서 생성 및 정리
- 상위 `archive` 폴더 생성
- 이후 사용할 빈 보조 폴더 생성
- README 또는 인덱스 문서 생성

### 5-2. 조건부 이동 가능
- `Skin_Proj` 관련 문서성 자산 중, 실행 경로와 직접 연결되지 않는 안내 문서
- 단, 이 경우에도 먼저 참조 경로와 링크 영향을 점검해야 한다.

### 5-3. 오늘은 이동하지 않는 편이 더 안전한 것
- `Skin_Proj` 본체 폴더 전체 이동
- `Skin_wrinkle_proj/doc/pm/current`, `legacy` 재이동
- `skin_crop_data`

## 6. 오늘은 건드리면 안 되는 것
다음 항목은 오늘 건드리면 안 된다.

- `Skin_wrinkle_proj` 물리 위치 변경
- `Skin_diagnosis_proj` 물리 위치 변경
- `skin_crop_data` 물리 위치 변경
- `outputs` 이동
- `checkpoints` 이동
- `logs` 이동
- `scripts` 대규모 rename
- `src` import 구조 변경
- `config/configs` 병합 또는 삭제

이유:
- 경로 하드코딩
- 재현성 훼손 위험
- 내일 웹 PoC 기준선 추적 불안정
- 서로 다른 프로젝트의 미완료 변경과 충돌 가능성

## 7. 이동 시 영향받는 경로 체크리스트
### 7-1. config
- `config`와 `configs`가 동시에 존재하는지 확인
- 실제 사용 설정이 어디에 있는지 확인
- yaml 내부 절대경로 존재 여부 확인
- 실행 스크립트가 특정 설정 파일명을 직접 기대하는지 확인

### 7-2. script
- `Set-Location`
- `PYTHONPATH`
- 프로젝트 루트 절대경로
- `SKIN_CROP_ROOT`
- 로그 파일 출력 위치
- checkpoint 저장 위치

### 7-3. import
- `src` 기준 import 경로가 현재 프로젝트 루트를 전제하는지 확인
- 스크립트가 실행 위치에 따라 import가 달라지는지 확인
- `__init__.py`와 패키지 루트가 이동 후에도 같은 의미를 가지는지 확인

### 7-4. outputs
- metrics csv 위치
- predictions 위치
- reports 위치
- confusion matrix 위치
- 웹 PoC에서 직접 참조할 산출물의 경로 고정 여부

### 7-5. docs link
- GitHub 상대경로 유지 여부
- 로컬 절대경로 링크 제거 여부
- current/legacy 문서 간 연결 유지 여부
- 상위 hierarchy 문서와 하위 프로젝트 문서 간 링크 일관성
